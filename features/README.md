# Тестирование с Cucumber и Playwright

Этот каталог содержит файлы функций Cucumber и определения шагов для тестирования приложения с использованием Playwright.

Для дебаггинга упавших тестов предлагаются два инструмента:

1. Трассировка Playwright,
2. Отчеты Cucumber.

## Запуск тестов

Для запуска тестов используйте команду:

```bash
npm test
```

Подробная информация о доступных функциях выводится при запуске команды:

```bash
npm test -- --help
```

## Теги сценариев

Для управления выполнением тестов используются следующие теги Cucumber:

### @current

Тег для запуска конкретного сценария или небольшой группы сценариев.

**Использование:**

```gherkin
@current
Scenario: Проверка важной функциональности
  Given я нахожусь на странице списка
  When я выполняю поиск
  Then результаты должны отображаться корректно
```

```bash
npm test -- --current
```

**Особенности:**

- Запускает только сценарии с тегом `@current`.
- Исключает необходимость запуска всего набора тестов.
- Удобен для разработки и отладки отдельных сценариев.

### @trace

Тег для сохранения трассировки Playwright независимо от результата теста.

**Использование:**

```gherkin
@trace
Scenario: Проверка важной функциональности
  Given я нахожусь на странице списка
  When я выполняю поиск
  Then результаты должны отображаться корректно
```

**Особенности:**

- Трассировка сохраняется всегда, даже если тест проходит успешно.
- Полезно для детального анализа поведения приложения.
- Файлы сохраняются в каталоге `features/results/traces/`.

### @broken

Тег для маркировки временно неработающих или нестабильных сценариев.

**Использование:**

```gherkin
@broken
Scenario: Функциональность в разработке
  Given я нахожусь на странице
  When я выполняю действие
  Then результат должен быть корректным
```

**Особенности:**

- Исключает нестабильные тесты из общего прогона, запускаемого командой `npm test`. также они исключаются из CI/CD.

### @heavy

Тег для маркировки тяжелых или долгих сценариев, которые могут быть исключены из быстрого прогона.

**Использование:**

```gherkin
@heavy
Scenario: Долгая операция с большим объемом данных
  Given я загружаю большой набор данных
  When я выполняю сложную обработку
  Then результат должен быть корректным
```

**Запуск всех тестов кроме тяжелых:**

```bash
npm test -- --not-heavy
```

### Комбинация тегов

Теги можно комбинировать для более точного контроля:

```gherkin
@current @trace
Scenario: Отладка новой функциональности
  Given ...
  When ...
  Then ...

@heavy @trace
Scenario: Исследование проблемы в нестабильном тесте
  Given ...
  When ...
  Then ...
```

## Трассировка Playwright

Фреймворк тестирования использует [трассировку Playwright](https://playwright.dev/docs/api/class-tracing) для поддержки отладки неудачных тестов. Это существенно удобнее скриншотов и видео.

### Автоматическое сохранение трассировки при неудаче теста

Когда тест не проходит, его трассировка сохраняется в каталоге `features/results/traces/`. Трассировка включает:

- Скриншоты на каждом шаге
- DOM-снимки
- Сетевые запросы и ответы
- Консольные логи
- Видимость исходного кода
- Временную шкалу действий

Файлы трассировки следуют следующему шаблону именования:

```
имя_сценария_суффикс_устройства_YYYY-MM-DDTHH-MM-SS-SSS.zip
```

### Просмотр трассировок

Для просмотра собранных трассировок используйте инструмент командной строки:

```bash
npx playwright show-trace features/results/traces/ИМЯ_ФАЙЛА.zip
```

## Отчеты о тестировании

Отчеты о тестировании генерируются в следующих форматах:

- HTML-отчет: `features/results/reports/cucumber-report-{устройство}.html`
- JSON-отчет: `features/results/reports/cucumber-report-{устройство}.json`

## Структура каталогов

Артефакты тестирования организованы следующим образом:

```
features/
├── results/
│   ├── traces/      # Содержит трассировки Playwright для упавших тестов
│   └── reports/     # Содержит HTML и JSON отчеты, сгенерированные Cucumber
└── ...
```

Такая организация позволяет держать все файлы, связанные с тестированием, внутри каталога features.
